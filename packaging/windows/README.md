# The Windows build

The game is one codebase; Windows needs no code of its own beyond where a save
belongs (`%LOCALAPPDATA%`, see `persistence.py`) and a way to be a single
`.exe`. This folder is that way.

Nothing here runs on Linux -- **PyInstaller does not cross-compile** -- so the
build happens in CI, on a `windows-latest` runner:
`.github/workflows/windows.yml`.

## What is here

| file | what it is |
| --- | --- |
| `run.py` | the entry point PyInstaller freezes |
| `neverdeads_revenge.spec` | the PyInstaller recipe (one file, windowed, sounds inside) |
| `make_icon.py` | turns `assets/neverdeads-revenge-2.svg` into the `.ico` |
| `neverdeads_revenge.ico` | the icon, committed (generated by the script above) |

## Building it

**In CI** -- push a tag, or run the workflow by hand:

```sh
gh workflow run windows.yml
```

The `.exe` lands as a workflow artifact, and on a `v*` tag it is attached to the
release.

**By hand, on a Windows machine** -- from the repository root:

```bat
py -3.12 -m venv .venv
.venv\Scripts\pip install -e ".[dev]" pyinstaller
.venv\Scripts\pytest -q
.venv\Scripts\pyinstaller packaging\windows\neverdeads_revenge.spec
```

`dist\NeverdeadsRevenge2.exe` is the game. It writes its save to
`%LOCALAPPDATA%\neverdeads_revenge2`.

## The icon

Only regenerated when the mark changes:

```sh
./.venv/bin/python packaging/windows/make_icon.py     # on Linux is fine
```

Vista and later read PNGs straight out of an `.ico`, so the script writes the
container itself and needs no image library.

## Notes

- The **font is a system face** (`font.py` walks a list ending in Consolas and
  Courier New), which is why no font is bundled: Windows has Consolas.
- **Sound** is `miniaudio`, which is WASAPI on Windows and needs nothing
  installed.
- The onefile build unpacks to a temporary directory on start, so the first
  window takes a moment. That is the price of a single file; an `--onedir` build
  starts faster but is a folder to zip.
